Process Walkthrough

How the Full Pipeline Works

From raw audio to AI-enriched insight in five automatic steps.

1

Audio Ingestion

You upload a WAV, MP3, FLAC, or OGG file — or record directly from your microphone via the browser. The system accepts any length of audio; files longer than approximately two minutes are automatically divided into overlapping segments so no content is lost.

2

Audio Normalisation

The audio is converted to the format the AI model expects: a single audio channel (mono) sampled at 16,000 measurements per second. This step handles any combination of input formats, stereo recordings, or unusual sample rates automatically.

3

Speech Recognition (IBM Granite Speech)

IBM's Granite Speech 5.0-2B model — a 2-billion-parameter neural network — processes the audio and generates a precise written transcript. The model supports transcription and translation across six languages in a single pass. A detailed timing profile records exactly how long each stage took.

4

AI Language Model Processing (Optional)

The transcript is passed to whichever AI assistant is configured — a local model on the same machine, or a cloud service. The model receives your instruction ("summarise," "extract action items," etc.) and generates a response. The system intelligently skips this step if transcription produced an error, preventing wasted API calls.

5

Saved Output

Results are saved to disk in a timestamped JSON file containing the full transcript, AI response, processing timing, and metadata. The transcript is also available as a downloadable text file directly from the browser.

The Speech Recognition Engine

IBM Granite Speech 5.0-2B is a two-stage neural network. The first stage is a speech encoder — it listens to the audio waveform and produces a rich numerical description of every spoken sound. The second stage is a language model decoder — it takes that description and generates natural written text. The two-billion parameters of the combined model capture nuances of accent, background noise, and domain-specific vocabulary that simpler approaches miss.

Automatic Hardware Optimisation

On startup, the system scans the host machine: it checks for NVIDIA GPUs and their available memory, Apple Silicon chips, CPU core counts, and total RAM. It then selects the fastest available processing mode — GPU acceleration where possible, Apple's Metal GPU stack on Macs, or CPU-only with additional optimisations on commodity hardware. A minimum of 4 GB free memory is recommended for GPU inference; 8 GB RAM for CPU-only operation.

Security & Reliability

Built for Trustworthy Operation

Privacy by Design

When configured with local AI backends (Ollama, LM Studio, or llama.cpp), the platform processes audio and generates responses entirely on your own hardware. No audio, transcript, or AI response is ever transmitted to an external service. Cloud backends (OpenAI, Anthropic) are opt-in and clearly labelled.

✔ No cloud audio upload ✔ No usage analytics ✔ API keys in local .env only ✔ Output files stay on disk

Secure Browser Access

Modern browsers require an encrypted (HTTPS) connection before allowing microphone access. The setup script automatically generates a self-signed TLS certificate for local use. The private key is stored only on the local machine and is excluded from any version control commits, preventing accidental credential exposure.

✔ HTTPS on localhost ✔ Keys never committed to git ✔ Auto-generated, auto-detected

Error Handling & Graceful Degradation

🔇 Microphone Unavailable

If no TLS certificate is present, the microphone button is hidden automatically. File upload continues to work normally. The application never crashes on missing hardware.

⚠️ AI Backend Unreachable

If the configured AI backend is offline, the transcription step completes successfully and the AI step is skipped with a clear on-screen message rather than failing silently or crashing.

💾 Insufficient Memory

The hardware detector warns when available memory may be insufficient to load the model, and suggests alternative precision settings. The application falls back to CPU processing automatically.

📁 Audio Format Issues

Four audio-loading libraries are tried in sequence. If one fails (e.g. due to a missing system codec), the next is attempted automatically — ensuring maximum compatibility with real-world audio files.

Quick Start

Up and Running in Under 10 Minutes

Three commands to a fully operational speech intelligence platform.

Step 1 — Setup

Run the one-time setup script. It creates an isolated Python environment, installs all dependencies, and generates the HTTPS certificate automatically.

bash scripts/setup.sh

Step 2 — Configure

Edit config/config.yaml to choose your AI backend, or set environment variables in a .env file. The default configuration works out of the box with Ollama.

ollama pull granite4.2:latest

Step 3 — Launch

Start the application. The script prints the URL and opens in background mode. Open the printed address in any modern browser.

bash scripts/start.sh
